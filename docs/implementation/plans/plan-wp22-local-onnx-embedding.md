# WP-22 — 本地多语言 ONNX Embedding（P3 第 17 项）

依据：PRD FR-120 的「必要规则」（`PRD.md:993-1000`：「本地模式不得在未授权时上传项目文本」、
「Embedding Provider 可替换」）、PRD §16 v1.0 清单第 17 项、AGENTS §6（新增第三方依赖前检查许可证与
维护状态）、SECURITY §15（SBOM 是 CI gate）、STATUS §0k（记的三个限制：语义通道需要 Provider、
最新 500 条候选窗、召回评测集）。

## 0. 侦察结论（**全部是实测，并且实测改变了方案**）

这个包的每一块都先跑了一遍才写下来，因为 ONNX 是最容易「看起来能行」的一类依赖：

| 事实 | 证据 | 后果 |
|---|---|---|
| **ORT 运行时能加载，且要挑版本** | `LoadLibrary` 实测：官方 1.20.1 release 的 dll **失败**（win32 error 126），Python wheel 里的 dll **成功** | 用 wheel 里那个 |
| **126 的原因查到了具体 DLL** | 解析 PE 导入表：官方构建导入 `api-ms-win-core-path-l1-1-0.dll`，**本机没有**；wheel 的构建不导入它 | 这不是「缺 VC++」这类猜测，是一条可复核的事实 |
| **绑定版本必须配对** | `yalue/onnxruntime_go` v1.20.0 要 ORT API 22、v1.19/1.18 要 21、**v1.17.0 要 20**；wheel 的 dll 是 1.20.1（API 20） | **v1.17.0**，实测 `onnxruntime OK, version: 1.20.1` |
| **真推理跑通了** | 本地用 Python 造了一个 1220 字节的 ONNX 模型（Gather + ReduceMean），Go 侧 `NewAdvancedSession` + `Run` 得到 **8 个 float** | 会话、张量编组、输出形状全部被真跑过 |
| **v1.17 的 API 形状与新版不同** | `Run()` **不带参数**，输入输出在 `NewAdvancedSession` 时传入 | 写代码前先读过源码，不是照抄新文档 |
| **不需要下载任何模型** | 模型由本仓的脚本在本地构造，权重可读、可复算 | 测试不依赖网络，也不把二进制塞进仓库 |
| **HuggingFace 不可达** | `curl` 超时 | 真实多语言模型**无法从网络取得** |
| **本机确实有一个真模型** | `find` 命中 `all-MiniLM-L6-v2`（43 MB ONNX + `vocab.txt`），在**另一个项目**的 data 目录里 | 它能证明**适配器**，见下 |
| **它端到端跑通了** | Go 侧三个 int64 输入 → `last_hidden_state [1,5,384]` → attention-mask 加权平均池化 → 384 维归一化向量 | 会话、编组、池化、归一化全部真跑过 |
| **它产生了真实的语义信号** | 余弦：`cat~kitten 0.6169` / `cat~dog 0.5572` / `cat~stock 0.0882`（英语） | 管道不是「看起来能行」，是**能行** |
| **但它读不了中文，而且这是实测的** | 词表覆盖：canary 的 27 个汉字**只有 11 个**在词表里；`沈`/`砚`/`红`/`色`/`渡口` **全部不在**。禁令句分词 16 片里 **10 片是 `[UNK]`** | **PRD 第 17 项的「多语言」在本机无法满足** |
| **我的第一个探针是错的，错在读词表** | `vocab.txt` 是 CRLF，我按 `
` 切分给每个词留了 ``，于是**每次查表都失败**、每段文本都退化成同一串 `[UNK]`，四段文本余弦全是 1.0000 | 与「模型没信号」是同一现象、相反原因——这条记下来，因为它是最容易误判成模型问题的读法缺陷 |

**这些结论合起来决定了这个包的范围**，而且必须说清楚：**适配器可以做完整、可以做真、可以测，
并且已经用本机那个真模型端到端验证过；但它读不了中文，而 PRD 第 17 项的名字就叫「本地多语言 ONNX
Embedding」。** 本包因此**不宣称交付了「多语言」**：它交付的是**一个经过真实验证的本地 embedding
适配器**，以及**一份把「模型从哪来、怎么换、缺什么」写清楚的接缝**。冒充前者是这一项最容易犯的
错，所以 §5 单独写它。

## 1. 裁定

1. **新增依赖 `github.com/yalue/onnxruntime_go v1.17.0`**（BSD-3-Clause，需核对），
   以及 **`onnxruntime.dll` 作为运行时资产**——后者是二进制分发，ADR 必须写明来源、版本、
   校验和与许可证，并写进 SBOM 与 THIRD_PARTY_NOTICES。
2. **不把 dll 提交进仓库**：它 13 MB，且是平台特定的。适配器按**查找顺序**解析它
   （显式配置路径 → 与可执行文件同目录 → 系统 PATH），找不到就 **fail-soft**：本地 embedding
   禁用并给诊断，语义通道回落到既有路径——**这正是 STATUS §0k 记录的现状**，所以「没装运行时」
   与「装了但没模型」都是可解释的状态，而不是崩溃。
3. **`Embedder` 端口已经存在**（`application/memory/ports.go`），本包只是新增一个实现，
   **不改端口形状**。可替换性（FR-120「Embedding Provider 可替换」）因此是结构保证。
4. **模型路径与 tokenizer 都来自配置**，不写死。**词表由模型目录里的 `vocab.json` 提供**，
   tokenizer 用**最简可行**的：小写化 + 按空白/标点切分 + 未知词哈希到 `[UNK]`。
   **这不是「多语言分词」，这一点必须写明白**（§5），它让管道可测，并且让真实模型接进来时
   只需要换 tokenizer。
5. **不实现 sqlite-vec**：第 17 项的括号里写着「可选」，而**最新 500 条候选窗的召回限界**在
   `ScaleRecords` 测试里已被锁住；换索引是一次独立的、有自己风险的技术变更，本包只**记录**
   它仍开放。
6. **模型的构造脚本进仓库**（`scripts/gen-embedding-fixture.mjs` 或 Python），
   `--check` 能复算——与 canary fixture 同一套纪律：**生成物由生成器证明**。

## 2. 实现

- `internal/infrastructure/onnx/embedder.go`（新）：实现 `application/memory.Embedder`。
  - `Available()` / `Diagnostic()` 的形状与 MediaEngine 一致（找不到运行时是**禁用**，不是失败）；
  - **逐条文本推理**，批量时循环——不发明 batch 语义；
  - 输出归一化（`memory.Normalize` 已存在），维度来自模型的输出形状而不是配置；
  - 失败分类：运行时缺失 / 模型缺失 / 模型不兼容 / 推理失败，各有自己的诊断。
- `internal/infrastructure/onnx/tokenizer.go`（新）：最简 tokenizer + 词表加载 + 上限。
- `media_wiring` 之外新增 `embedder_wiring.go`：按配置构造，缺失就是 nil（既有语义通道据此关闭）。
- `scripts/gen-embedding-fixture.py`（新）+ `testdata/models/tiny-embedding.onnx`（**生成物**，
  1.2 KB，可复核）。

## 3. 测试

- **真推理**（不是 mock）：加载 fixture 模型，断言输出维度、归一化、**相同文本得到相同向量**、
  不同文本得到不同向量。这一条是本包的核心，因为它证明的是**适配器**而不是模型质量。
- **fail-soft**：运行时路径为空/指向不存在的文件 → `Available()==false` 且 `Diagnostic()`
  说明原因，**不 panic**。
- **模型不兼容**：拿一个不是 embedding 形状的模型（同一个 fixture 换成输出 2 维）→ 明确报错。
- **tokenizer**：未知词、空串、超长文本（截断到上限）、非 ASCII（中文按字节散列进桶，
  这是限制不是特性，测试把这**写下来**）。
- **端口一致性**：`var _ appmemory.Embedder = (*Embedder)(nil)`。
- 变异：维度校验、归一化、截断上限、可用性判断、诊断分支。

## 4. 明确不做

- **真实多语言模型**：HuggingFace 不可达（实测），且下载 ~90 MB 的二进制不在本包授权范围。
  适配器**接受**它，`tokenizer` 与模型路径都可配置，缺的只是文件。
- **sqlite-vec / 换索引**（裁定 5）。
- **ONNX 的 GPU/执行提供器**：只用 CPU 默认，不配置 provider。
- **模型下载 UI**：需要网络与许可决策，另开包。

## 5. 风险与诚实声明（这一节是本包最重要的部分）

- **fixture 模型不是语言模型。** 它的权重是随机数，输出向量**没有任何语义**。它证明的是
  「会话建立、张量编组、输出形状、归一化、fail-soft」这些管道事实。**任何「语义检索质量因此
  变好」的说法都是假的**，本包不这么说，STATUS 也不这么写。
- **tokenizer 不是多语言 tokenizer。** 中文会被按字节/区段散列进桶，**同义与近义完全丢失**。
  真实模型需要真的 tokenizer（BPE/SentencePiece），本包**只留接缝**。
- **dll 不进仓库**：所以「装好了运行时」是一个**用户/打包动作**，本包提供查找顺序与诊断，
  不提供安装器。这一条与 P3 第 25 项（稳定安装与升级）相连，STATUS 会点出来。
- **本包的价值因此是**：把「Provider 可替换」从**声明**变成**已验证的实现**，并让语义通道在
  本地可用**管线级**成立；模型质量那一半需要一个模型文件，而它不在这台机器上。
