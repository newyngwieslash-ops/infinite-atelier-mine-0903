## 2. 五种事实分类（禁止一个 DONE 合并）

对每个 FR 行，本计划按以下五类之一陈述（TRACEABILITY 更新时使用同一词汇）：
1. **代码已实现**：有测试证据的软件事实（如 T07 速率限制）。
2. **用户可操作**：UI 入口存在且 Binding 接通（如 T05 编辑控件）。
3. **离线已测**：本机/CI 可复现的测试证据（如 AC-E2E-002 canary）。
4. **真实/原生已验收**：真实供应商调用、原生窗口、VM 安装态证据（目前仅文本/图片适配器协议级、EXE 本机启动；VM 未做）。
5. **获准延后**：有 ADR/裁定文档来源的范围决定（如加密备份 ADR-0016、PDF v1、macOS/Linux v1.5）。

## 4. PRD §16 与 ACCEPTANCE §15 冲突记录

- **PRD.md:1675**（v1.5 清单）将 macOS/Linux 打包列为 v1.5；**PRD.md:707** 的版本矩阵标 macOS/Linux v1.0「否」。
- **docs/ACCEPTANCE.md:707** 同一矩阵标 v1.0「可选验证」、后续「必须验证」——与 PRD 一致，无实质冲突；计划 §1.2 所述「差异」实为措辞层级差异（PRD 用「优先级」，ACCEPTANCE 用「验证强度」）。
- **结论**：以 PRD §16 为版本范围事实来源（Windows 首发），ACCEPTANCE 矩阵作为各版本验证强度口径。两者互不矛盾；待 D1 获产品确认后在封板（RP-12.4）统一措辞。本决定不修改任何原文。
