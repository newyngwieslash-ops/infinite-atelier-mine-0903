## 1. 十项裁定（写入 ADR-0014，全部记为可反驳）

| # | 裁定 | 理由与代价 |
|---|---|---|
| **1** | **`memory_items` 是记忆存储；`agent_messages` 仍是 runtime 的 transcript。** episodic 项在 runtime 记录 transcript 的**同一调用**中经端口写入，二者不可能漂移 | transcript 的生命周期是 run 的（`ON DELETE CASCADE`），记忆是用户的（可固定/编辑/删除/重建向量）。把 `locked`/`embedding_blob` 塞进 transcript 会让「删除这条记忆」变成改 transcript。代价：episodic 内容一份副本。§14.1 的 `source_type='message'`/`source_id` 就是这条引用。★ |
| **2** | **summary 的源就是消息**：`memory_summary_sources(summary_id, source_message_id, source_order)`（§14.2 字面），层级摘要用 `memory_entity_links(relation_type='summarizes')` 连子摘要（§14.3 字面） | AC-MEM-004 的原文是「Summary **关联源消息表**」；role/agent/time 由消息本身携带，UI 一跳即达。★ |
| **3** | **Recent 通道继续读 `agent_messages`**（`RecentMessages` 及其 6 个测试**不动**） | AC-MEM-001 的现有覆盖保持有效，WP-10 不推翻已评审断言。代价：两条读路径并存，靠 §12.1 的通道划分各自成立。★ |
| **4** | **Embedding 三层**：`CapabilityEmbedding` + `KindMockEmbedding`（确定性特征哈希，同一端口）+ OpenAI 兼容 `/v1/embeddings` 适配器（复用受控 client） | 用户已选。特征哈希同时是 FR-120 MVP 的「关键词降级」路径。代价：反转 `provider_test.go:150` 的断言（须改写并注明原因）。★ |
| **5** | **Embedding 是 opt-in**：项目 `embedding` 层策略未指名 provider 时，语义通道不可用并**如实报告**，不静默降级、不外发文本 | SECURITY §16.2「Embedding 默认本地优先」+ PRD「本地模式不得在未授权时上传项目文本」。★ |
| **6** | **摘要是确定性抽取式的**（`extractive/v1`），不新增 agent/stage | 用户已选。§12.2 的「Recent 未摘要消息」窗口 = 无 source 行引用的消息。AC-MEM-004/005 因此可离线独立验证。★ |
| **7** | **确定性检查在 LLM Supervisor 之前跑**，其发现以 `source=deterministic` **合并进同一份 ReviewReport**；有效 `passed` = 模型通过 **且** 无阻断性确定性发现 | 用户已选，且是 §11.4 的字面要求。迁移 000019 给 `review_issues` 加 `source`（DEFAULT `'llm'`，旧行语义不变）。★ |
| **8** | **向量索引 = SQLite 精确检索**，`VectorIndex` 四方法端口（ARCHITECTURE §12.3 字面）；float32 BLOB 小端；归一化点积；scope 过滤在 SQL **打分之前**；只搜同 `embedding_model`/`version` 的行 | §14.5「模型变化不覆盖旧向量，重建后切换索引版本」+ ADR-0002:68 拒绝动态扩展加载。★ |
| **9** | **记忆中心按 Agent 中心的先例做成 Studio 分区**（`memory`） | PRD IA 把记忆中心列为全局模块，但 Agent 中心（同属全局模块）在本仓库就是 Studio 分区。代价：与 IA 的字面分组不同，记入 STATUS。★ |
| **10** | **不新增写入类记忆工具**；语义记忆由用户命令（§16 `RememberProjectFact`）与管线写入（§12.4 的四个来源） | 工具是模型动作，§12.4 明列「不要把未批准模型候选/推测当高置信事实」。只加深 `memory.deep_recall`（读）。★ |

★ 均因细节未经用户逐条确认而按推荐执行，全部记为可反驳。

## 4. 管线接入（G3 —— 本包最关键的既有缺口）

**`agentruntime.Runtime`** 增 `Options.Memory MemoryPort`（端口：`Recall` + `RememberMessage`）。语义：
- `Run` 在 `CreateRun` 之后、**首次模型调用之前**写入用户消息（§12.2 的顺序），并同时写 episodic 记忆项 —— **同一调用，不可能漂移**（★裁定 1）。
- `Invocation.Memory` 终于有生产填充者：由 `stagepipeline` 在第 7 层填入召回结果（带 provenance）。
- 端口为 nil 时：不召回、不写记忆，**如实**（不是降级：是「本构建没有记忆存储」）。`agentWiring` 在生产中总是供给，并加一个 wiring 测试断言组合出的 runtime 确实持有它（WP-09 那类「接口无真实路径」缺陷的关闭方式）。

**`stagepipeline`** 增 `Options.Memory` 与 `Options.Checks`（两个可选端口）：
- `RunStage`：构建 `Invocation` 前召回（`ExcludeMessageID` 当前轮）→ 填第 7 层。
- `RunSupervision`：**先** `Checks.Check(stage, artifactVersionID)` → 把确定性发现渲染进 supervisor 的 Task（信任层，且要求模型**不要重复**已报出的故障）→ 跑 LLM → **合并**（按 `(rule, entityType, entityId, field)` 去重）→ 有效 `passed` = 模型 `passed` **且** 无阻断性确定性发现；severity 取最大 → 一次 `RecordReview` 写入两份来源。既有 `ReviewReport.Validate` 的「passed 不得带 major/critical」会在合并出错时 fail closed。

**`agenttools`**：只加深 `memory.deep_recall`（读，返回摘要/语义/来源/窗口名，保持现有 `messages` 键不破坏已授权的 skill 与 mock），`scripts/gen-tool-schemas.mjs` 同步描述文本。

## 5. 一致性（scope 13/14）

**`internal/domain/consistency/`（新，纯函数）** + **`internal/application/consistency/`（新，装载与检查）**：

规则（每条：`Rule/Severity/EntityType/EntityID/Field/Problem/Suggestion/Evidence/AutoFixable`）：
1. **服装连续性** —— 分镜行引用的 costume usage（`asset_usages` consumer=shot）必须与该角色在对应事件序位生效的 `character_states.costume_asset_version_id` 一致 → **AC-E2E-004 的注入错误由代码定位到 Shot 6**，不靠模型扮演。
2. **道具连续性** —— 引用的 prop 资产的 story entity 必须是该场景来源事件的参与者。
3. **场景/地点连续性** —— 同场景相邻行不得指向不同 location；location 资产必须存在且有批准版本。
4. **覆盖与顺序** —— 批准剧本的每个 shot 恰有一行，ordinal 连续无重。
5. **时长** —— 行的时长总和与剧本版本 `estimated_duration_seconds` 的偏差在容差内。
6. **资产批准** —— 引用的 asset version 必须是当前批准版本（§8.4）。
7. **Event Graph 分离**（§14.5/§12.1）—— 记忆召回**不吸收**故事事实；断言 `memory_items` 不含 story graph 内容，事实经结构化通道进入 prompt 第 6 层（`ApprovedFacts`）。

**阻断等级**：`breaking`（1/2/6）→ 强制 `passed=false`；`review_required`（3/4/5）→ 报告但可人工放行；无 `informational` 干扰。

## 10. 风险与诚实声明

- **最大风险：本包触及已评审的共享代码**（`agentruntime.Runtime`、`stagepipeline`、`provider` 能力表、`review_issues` 读路径）。缓解：`Runtime` 的新端口是**可选**的（nil = 无记忆，语义明确），`stagepipeline` 的两个端口同理，`review_issues.source` 有 DEFAULT 且旧行语义不变；每一步先跑 `go test ./...` 确认 WP-07/08/09 全绿再前进。
- **次大风险：Embedding 反转既有断言**（`provider_test.go:150`）。缓解：改写该测试并在注释里写明「由 WP-10 反转，理由是 ROADMAP 第 17 项与用户裁定」，不删除、不静默放宽。
- **第三风险：确定性规则的假阳性**会误伤正常分镜。缓解：规则只在数据齐备时判定（缺数据 → 跳过而非报错），每条规则有正反两向测试，canary 的 `expected-storyboard.json` 必须零发现。
- **第四风险：摘要的机械质量**。缓解：ADR 明写 `extractive/v1` 是 MVP 且语义摘要属 V1；摘要文本可从源消息逐字复原，因此 AC-MEM-004 的 provenance 比模型摘要更**可验证**。
- 时间/代价：真实 Provider 一律不碰，所有测试走 mock/fake；`go test -race` 在本机是**环境失败**，如实报告。
