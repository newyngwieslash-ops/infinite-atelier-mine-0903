# WP-04 — Legacy 项目迁移与画布后端适配

## 需要先固化的三项决策（已按最佳判断选定，实施时写入 ADR）

1. **ID 格式 = UUIDv7**（ADR-0005）。DOMAIN_MODEL §2.1 要求"UUIDv7 或 ULID，在 WP-01 ADR 固化"，但该 ADR 从未存在，现有 ID 只有 job 包的临时格式。用 `crypto/rand` 自实现约 30 行（无新依赖），时间有序利于索引；job 包旧 ID 不追溯重写。
2. **物理文件表沿用 `file_objects`**，不新建 `physical_files`。DOMAIN_MODEL 的 `physical_files` 与 WP-01 的 `file_objects` 是同一条事实（SHA-256、大小、MIME），建两张表会产生双重真相。命名差异写入 ADR-0005。
3. **E2E 采用 Playwright**（`@playwright/test`，Apache-2.0，仅 devDependency；宿主已有浏览器缓存）。ACCEPTANCE T6 与 ARCHITECTURE §19 均指定 Playwright。若环境确实无法运行，如实标 BLOCKED，不伪造通过。

## 1. 前端切流方式（关键取舍）

**在 secure/desktop 模式下彻底切换**：`web/src/services/desktop/` 新增 `canvas-adapter.ts`，定义 `CanvasPersistenceAdapter` 接口，两个实现：

- `GoCanvasAdapter`（桌面模式）：经新 binding 读写 Go Core；保存为防抖命令，读取为查询。
- `LegacyCanvasAdapter`（浏览器开发模式）：保留现有 localForage 路径，因为浏览器里没有 Go Core。

`project.tsx` 的渲染与交互**不动**（这是 AC-CANVAS-004 的风险点），只替换持久化接缝：现在 `updateProject` 写 zustand 持久化 store，改为写 adapter。secure 模式下 `useCanvasStore` 关闭 localForage 持久化，`projects` 退化为 Go 查询的内存投影（符合 ADR-BASE-004"Zustand 只保留 UI/临时状态"）。迁移完成前，旧数据只读可打开（ROADMAP 第 12 项）。

## 2. Schema — `000004_projects_canvas.sql`（前向，单一迁移）

按 DOMAIN_MODEL §12/§18 字段与索引建表：

- `workspaces`（种子默认 local workspace，不可删）
- `projects`(id, workspace_id FK, project_type∈free_canvas|drama, name, description, language, status∈active|archived|trashed, cover_asset_version_id, deleted_at, revision, …)
- `canvas_documents`(project_id FK, canvas_kind∈free|drama|episode|storyboard|asset, viewport_json, background_json, revision)
- `canvas_nodes`(canvas_document_id FK, node_type, entity_type/entity_id/entity_version_id **三者同空或同非空 CHECK**, position_x/y, width, height, z_index, ui_state_json, **legacy_metadata_json**, revision)
- `canvas_edges`(from/to FK, relation_type 默认 **`generic`**（PRD FR-130：旧无类型连线迁移为 generic 不丢失）, from_port, to_port, required, validation_status, metadata_json, legacy_metadata_json, revision)
- `canvas_chat_sessions`(canvas_document_id FK, title, messages_json, revision)
- `assets` / `asset_versions`(UNIQUE(asset_id, version_number)) / `asset_files`(→ file_objects FK, role)
- `generation_history`（**偏离 DOMAIN_MODEL 的映射，写入 ADR**：§20.1 说 history→provider_request/job，但那是真实审计行，伪造等于造假审计；改为专用留存表 + id 映射 + 报告）
- `legacy_imports`(source_fingerprint, status, mode, report_json, warnings_json, …) 与 `legacy_id_map(kind, legacy_id, new_id, import_id)`（5 种映射 kind 按 §20.1）
- 索引按 §18；`generation_jobs.project_id` 保持无 FK（既有 `''` 行无法满足），记录为已决事项
- 遵守 `splitSQL` 限制：字符串字面量内**不得出现分号**

## 3. Go 分层

- `internal/domain/project`：Workspace/Project/CanvasDocument/Node/Edge/ChatSession + 状态集、不变量、revision 规则
- `internal/domain/asset`：Asset/AssetVersion/AssetFile + approved 唯一性规则
- `internal/application/projects`、`internal/application/assets`：命令与查询、revision CAS
- `internal/application/migration`：LegacySnapshot 校验 → 变换 → **单事务导入**（事务内不做网络；导入前 `Pause()` 调度器、导入后 `Resume()`，避免 MaxOpenConns=1 下长事务饿死 job worker）→ 计数与哈希比对 → 报告与告警落库
- `internal/infrastructure/database/{projects,canvas,assets,legacy}.go`：SQL 只在此层
- `internal/infrastructure/archive/zip.go`：加固的 zip 读写（路径穿越、符号链接、条目数/单条/总量/压缩比上限、重复规范化路径、Unicode 规范化），AC-SEC-002 语料测试同时落地
- Bindings（窄面，沿用 fail-closed/`toAppError`/无路径无密钥约定）：`ProjectBinding`（项目+画布+chat）、`AssetBinding`（资产+历史）、`MigrationBinding`（预检/分块上传/导入/报告）、`BackupBinding`（导出/校验/恢复）

**大文件迁移通道**：Go 读不到 IndexedDB，前端必须把 blob 交出来。经 binding 传二进制只有 base64 一条路，整文件会爆内存。设计为**分块**：`BeginLegacyFile` → `AppendLegacyFile(chunk ≤4 MiB)` → `FinishLegacyFile`，Go 落临时文件、流式 SHA-256、按上限校验后原子提交进 FileStore，失败清理临时文件。不引入本地 HTTP 服务（避免新增攻击面）。

## 4. 导入流程（对应 AC-LEGACY-001/002/003）

```
前端提取 legacy 快照（版本化 manifest，含各 store 原始 JSON + blob 分块）
→ Go 预检（schema/大小/路径/计数）
→ 迁移前 VACUUM INTO 快照
→ 变换（node/edge/viewport/chat/history/media；未知 node_type 与未知字段进 legacy_metadata_json + warning）
→ 单事务导入（文件先内容寻址入库；DB 失败→回滚，无半成品）
→ 计数/哈希比对 → 写 legacy_imports 报告
→ 标记已迁移；旧数据只读保留（不删除，删除属 WP-12）
```

- **幂等**：`source_fingerprint`（项目 id + 标题 + 节点/边计数 + 媒体哈希）命中已完成导入 → 报告"已导入"；用户可选 `copy` 模式（全新 ID + 新副本）；**默认不覆盖**
- **回滚**：单事务 + 临时文件清理 + 阶段化错误报告（阶段名进稳定错误码）

## 5. 备份 v1（无密钥）

Go 侧 `manifest.json + app.sqlite 快照 + files/ + checksums.txt`，导出前 checkpoint，导出后全文扫描断言无 test key/Authorization/Cookie；导入在临时目录校验（路径/计数/大小/压缩比/manifest schema/逐文件哈希）后原子替换。单节点加密备份不在本包。

## 6. 前端

- `services/desktop/{projects,assets,migration,backup}.ts` 客户端 + 事件订阅
- `canvas-adapter.ts`（双实现，见 §1）
- 迁移界面：画布列表页"导入旧项目"入口 → 预检/预览/确认/进度/报告对话框（不新增路由），报告可回看（读 `legacy_imports`）

## 7. 测试与 fixtures

- **先建 fixtures**（AGENTS 要求）：`testdata/old-projects/{minimal,all-node-types,missing-media,malformed-metadata}` + `testdata/LICENSES.md` 声明为原创合成数据
- Go 单测/集成：迁移升级（`wp04Migrations` fixture + 行保留/约束/回滚）、域不变量、仓储、导入变换/幂等/回滚、zip 安全语料、备份往返与密钥扫描
- 前端：`node:test` 纯逻辑 spec（manifest 提取与变换、adapter 路由）
- Playwright：聚焦 AC-CANVAS-004（增删/多选/框选/缩放/平移/撤销重做/连线/小地图/裁剪分割掩膜）+ 旧项目导入；对 loopback dev server 跑，网络用 route interception 保持密闭。无法在 E2E 层验证的（如需要真实 provider 的生成链路）由 Go 侧 httptest 覆盖，并在 STATUS 中逐条说明哪一层覆盖了哪一项
