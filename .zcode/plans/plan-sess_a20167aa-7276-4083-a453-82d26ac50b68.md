# WP-02 实施计划（待批准）

## 目标
仅完成 **WP-02 — Secret、网络安全与 Provider Gateway 基础**：用 Windows Credential Manager 保存 Secret、通过 Go Core 执行受控 Provider 网络请求，并实现第一个 OpenAI-compatible 文本生成/流式适配器。

## 实施边界
- **包含：** SecretStore、Provider 元数据、SQLite secret reference、SSRF 防护 HTTP client、Provider Registry、文本适配器、健康检查、审计、窄 Wails Binding、前端安全状态/迁移提示、普通导出与备份的 secret 排除、静态安全扫描和测试。
- **不包含：** 图片/视频/音频迁移、持久化 Job、Agent、Workflow、Memory、Drama 领域能力、完整备份恢复重构、真实 Provider 调用。
- **安全保证：** 不提供 plaintext fallback、不将 key 返回前端、不暴露 `Resolve` Binding、不提供 generic fetch / arbitrary proxy。

## 具体步骤
1. 修正 `STATUS.md` 的 WP-01 表头/正文状态不一致，记录 WP-02 开始基线。
2. 新增 Provider 领域类型、稳定安全错误分类与 Application ports/services。
3. 新增前向 SQLite migration：`secret_references` 与 provider 配置元数据；不存 secret value，不修改 `000001_foundation.sql`。
4. 实现 Windows-only Credential Manager 适配器（`advapi32` Credential API）和 non-Windows unavailable 后端；增加 fake 和自有凭据清理测试。
5. 实现受控 Provider HTTP：严格 URL/host/port/DNS/IP/redirect/TLS 验证、已验证 IP 拨号、超时和响应边界。
6. 实现 trusted registry、OpenAI-compatible text generate/SSE stream/cancel、health check 与脱敏 audit。
7. 将组件接入 `app.go`/`main.go`，新增仅暴露状态、配置、删除/替换及文本请求的 Wails bindings；重新生成 bindings，绝不手改。
8. 前端新增 desktop Provider/Secret client，使用安全 DTO；在 secure mode 下禁用 query-key 初始化和动态 model script，迁移文本流；把旧多媒体路径保留为显式 legacy 兼容范围。
9. 普通 config export/import 与 ZIP backup 删除 raw secrets，并为 legacy 配置显示迁移提示。
10. 将动态执行与 secret/static scans 接入 verify scripts 和 CI，执行所有 Go/TypeScript/Wails/security 验证。
11. 完成独立 spec review 与 quality review，记录实际结果到 STATUS、TRACEABILITY、ADR/依赖记录，之后停止且不进入 WP-03。
